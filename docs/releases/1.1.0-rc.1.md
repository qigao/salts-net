# SaltsNet 1.1.0-rc.1

This release candidate adds CNet 2.3 strategy integration, native multi-Owner
hosting for LB/TCP proxy, and explicit STUN/ICE/TURN lifecycle ownership. It is
for evaluation; the known legacy STUN cleanup defect below remains unresolved.
Release preparation does not merge PR #48 or publish a package/tag.

## Changes

- LB and TCP proxy offer opt-in native SG hosting with 1/2/4 Owners, bounded
  admission and credits retained through actual terminal settlement. Target
  selection uses CNet policy; dedicated tunnels are not pooled or replayed.
- Email and LDAP use managed connection lifecycles while greeting, TLS upgrade,
  authentication and Bind continue to determine protocol readiness. SNMP keeps
  its UDP response validation and retry policy.
- STUN Binding and ICE server-reflexive gathering share a bounded transaction
  state machine. Gathering keeps the socket that established the NAT mapping.
  Failed ICE cleanup retains unpublished/candidate sockets and TURN children.
- New `stun_request_*` APIs expose one single-use, single-thread Owner with
  separate start, progress, result, stop and destroy phases. Inputs are copied;
  the destination must be a numeric IPv4/IPv6 address. Cleanup failure retains
  the Owner for retry. This API owns its backend and does not expose SG hosting.
- New `ice_agent_destroy_checked` and `turn_client_destroy_checked` accept a
  total cleanup budget and clear the caller's handle only after success.
  Existing public signatures remain available.

## Compatibility and SDK contents

- Qualification uses Salts.Native **2.3.0-rc.2** with SaltsUtils.Native
  **4.3.0-rc.2**. Build restoration still selects the newest official compatible
  release pair; inspect the prepared package's six manifests for the actual
  versions. Upgrade and roll back both dependencies together.
- Reconfigure and rebuild consumers against the matching SDKs. Do not mix
  Salts 2.1 binaries from SaltsNet 1.0.6 with this release's headers/libraries.
  The NuGet payload intentionally has no transitive Salts package dependencies;
  consumers must restore the matching dependencies explicitly.
- SDKs: Linux x64/ARM64, Windows x64, macOS ARM64, Android arm64-v8a and iOS ARM64.
  Relative to 1.0.6, Linux ARM64 is added and iOS simulator ARM64 is absent because
  the qualified upstream SDK pair does not ship that RID.
- CMake's numeric project/library version is **1.1.0**. The full package and tag
  version is **1.1.0-rc.1**, owned by `vcpkg.json`'s `version-semver`. CI verifies
  that its numeric core matches CMake. Existing library major version stays 1;
  this is not a claim of cross-Salts-version binary compatibility.

## Validation and limitations

The implementation baseline `fa215b57db9ba65e512bb220a3d8c18eaa0d4de0`
passed local Windows 39/39 source CTests and 2/2 independent installed consumers.
[Baseline six-platform CI](https://github.com/qigao/salts-net/actions/runs/38014753169)
passed four native platforms, each with 39/39 source tests and 2/2 installed
C11/C++17 consumers; these include real local STUN request/response and checked
cleanup. Android/iOS are compile/link/install qualifications, not device runs.
The versioned release preparation must independently pass on its exact commit;
its run and package SHA-256 are recorded in PR #48 before publication.

- **HIGH:** legacy synchronous `stun_binding_request` cannot return a retained
  transport Owner if cleanup times out. The new request API avoids that API
  limitation but does not fix the old implementation. Applications needing
  retryable cleanup must migrate to the explicit Owner; the legacy compatibility
  or deprecation decision remains open in [#50](https://github.com/qigao/salts-net/issues/50).
- Email/LDAP/SNMP still lack checked destruction. Legacy UDP DNS remains
  synchronous and outside the transaction deadline / ICE close wake boundary.
- Allocation/backend-initialization fault injection, full mixed-dependency
  isolation, public shared protocol hosting, TURN/ICE/SNMP nonblocking protocol
  state, WS/HTTP integration and corresponding installed consumers are pending.
- Existing proxy SG benchmark data is a limited workstation baseline. No general
  performance/scaling claim or equivalent UDP/WS comparison is made.

[#46](https://github.com/qigao/salts-net/issues/46),
[#49](https://github.com/qigao/salts-net/issues/49) and
[#50](https://github.com/qigao/salts-net/issues/50) remain open. Stop and drain
all live Owners before rollback; replace SaltsNet headers/libraries and the
qualified dependency pair together, then rebuild the consumer.

## Prepare and publish the same artifact

1. Keep PR #48 Draft during preparation. Pass local Windows configure/build,
   CTest, install and independent installed consumers before pushing CI.
2. Dispatch `native-sdk-release.yml` on the exact candidate branch with
   `prepare_release=true`. Wait for success, inspect `saltsnet-native-nuget`,
   verify six manifests, source SHA and package checksum. Preparation creates
   neither a tag nor a GitHub Release/package publication.
3. Only after separate publication authorization, create immutable
   `v1.1.0-rc.1` at that exact SHA. Dispatch the same workflow on that tag with
   `publish_from_run=<successful preparation run ID>` and `prepare_release=false`.
   It verifies source run provenance and package contents, then publishes the
   original artifact without rebuilding/repacking. RC push/tag runs do not
   automatically publish. GitHub Release is prerelease and does not become latest.
4. Verify tag, package and release assets. Existing assets must match SHA-256;
   never overwrite an existing version with different bytes. A failed attempt
   must be inspected before retrying. No release/publish path has been executed
   as part of preparation.
