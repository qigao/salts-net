# SaltsNet 1.1.0-rc.2

This release candidate fixes the synchronous STUN ownership defect present in
1.1.0-rc.1. It requires a source and ABI migration: the old two-argument function
is removed. It remains a prerelease for evaluation.

## STUN ownership and breaking migration

Previously, `stun_binding_request(config, mapped)` owned a stack transport. A
bounded cleanup failure could leave live I/O storage without a reachable Owner
and with a callback context whose stack lifetime had ended.

The new signature is `stun_binding_request(request, config, mapped)`. Create a
fresh `stun_request_t` with `stun_request_create` before calling it. The function
uses the existing start/progress/result state machine and returns a validation,
initialization, polling or terminal protocol status. It never stops or destroys
the Owner. On success it writes `mapped`; on error that output is unchanged.

On every path, separately call `stun_request_stop(request, cleanup_budget_ms)`.
Only after stop succeeds, call `stun_request_destroy(&request)`. Either cleanup
error retains the handle for another explicit cleanup attempt; destroy clears it
only on success. Protocol timeout and cleanup failure remain separate results.
There is no compatibility wrapper, fallback, automatic cleanup retry, hidden
thread or retirement queue. The request is single-use and all operations run
non-overlapping on one thread.

The synchronous function now shares start's numeric IPv4/IPv6-only destination
contract. Resolve hostnames before the call. Zero configuration values keep
port 3478, a 3000 ms per-attempt timeout and three total attempts. Each attempt
uses a fresh transaction ID and a fixed deadline; this is not RFC exponential
retransmission backoff. The migrated `stun_discovery` example requires a numeric
address through its argument or `STUN_SERVER_HOST` and reports cleanup failures.

Rebuild all consumers against matching headers and libraries. Do not run old
two-argument binaries against this SDK. Stop and drain every live Owner before
rollback, then replace headers/libraries together and rebuild consumers for the
previous signature. The published 1.1.0-rc.1 tag and package remain immutable.

## SDK and dependency qualification

The qualification pair is Salts.Native **2.3.0-rc.4** and SaltsUtils.Native
**4.3.0-rc.2**. Restoration still selects the newest official compatible release
pair; the six package manifests record the actual versions. Upgrade or roll back
the dependencies together. NuGet intentionally has no transitive Salts package
dependencies; consumers restore the matching dependencies explicitly.

SDKs: Linux x64/ARM64, Windows x64, macOS ARM64, Android arm64-v8a and iOS ARM64.
CMake's numeric project version remains **1.1.0**; `vcpkg.json` owns the full
**1.1.0-rc.2** package/tag version. This prerelease does not preserve rc.1's STUN
ABI or claim compatibility with SaltsNet 1.0.6's older Salts dependencies.

## Validation and remaining limits

The runtime fix in [PR #51](https://github.com/qigao/salts-net/pull/51), commit
`3bc6e4dcf9b3f34ae54a89a5b0037e936f6430e7`, passed local Windows MSVC Release:
39/39 source CTests, 2/2 independent installed C11/C++17 consumers, and the full
normal Release graph including examples. Its
[six-platform CI](https://github.com/qigao/salts-net/actions/runs/38023008826)
passed 39/39 source and 2/2 installed CTests on each of Windows x64, Linux
x64/ARM64 and macOS ARM64; Android/iOS passed build/install-only.

Regressions cover synchronous success, dropped-response retry, exact protocol
timeout, unchanged error output, deterministic destroy rejection before stop,
retained handle identity and stable protocol results through cleanup. Installed
consumers execute the changed synchronous ABI. The actual-backend zero-budget
stop test does not deterministically inject native cleanup timeout.

The versioned rc.2 candidate also passed local Windows MSVC Release: complete
configure/build, 39/39 source CTests, install and 2/2 independent installed
consumers, using the qualification pair above, before remote push.
After
merge, release preparation qualifies the exact merged source and packages all
six SDKs. PR #51 and the release publication record contain those final run IDs,
commit and SHA-256. Publication reuses the verified preparation artifact without
rebuilding or repacking; the RC release does not become latest.

Email/LDAP/SNMP checked destruction, legacy ICE UDP DNS deadline/cancellation,
allocation/backend-initialization fault injection, public shared protocol
hosting, full mixed-dependency isolation, TURN/ICE/SNMP nonblocking protocol
state, WS/HTTP integration and equivalent UDP/WS performance benchmarks remain
open in [#46](https://github.com/qigao/salts-net/issues/46),
[#49](https://github.com/qigao/salts-net/issues/49) and
[#50](https://github.com/qigao/salts-net/issues/50). No device-runtime or new
performance claim is made.
